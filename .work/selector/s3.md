# S3: когда selector не должен кодировать delta

Статус: **PREREGISTERED** — правило ниже зафиксировано до прогона `selector-s3.yml` и до просмотра признаков. Selector — [`delsk.simple-selector.v1`](README.md). Задача — [DELSK-009](https://github.com/definitely-stable/Shift-lab/issues/10) (H6), продолжена [решением о pivot](../decisions/2026-10-06-pivot-simple-selector.md).

## 1. Вопрос

Selector при K = 2 всегда тратит до двух вызовов кодера на target. Если ни одна база не даёт delta дешевле standalone, эти вызовы потрачены впустую. В pilot-v1 dev/cal таких targets 8 из 55, в X0 — 18 из 64. Можно ли отказаться от кодирования заранее, по 64 B descriptor, и не потерять заметную экономию?

## 2. Правило отказа (уровень `L`)

```text
abstain(t) ⇔ L > 0  и  metadata-order(t) пуст  и  max_b shared(t, b) < L
```

`shared` — число общих хэшей среди 8 наименьших хэшей объединения двух descriptors (числитель resemblance). Если есть metadata-кандидат (тот же путь и линия), отказа нет никогда: такая база дешёвая и обычно полезна. Уровни `L ∈ {0, 1, 2, 3, 4}`; `L = 0` — кодировать всегда, как в v1.

## 3. Метрики и выбор уровня (preregistered)

Population — targets pilot-v1 development/calibration и X0 (все 4 ячейки). Стоимость S и oracle O берутся из retained oracle rows, без нового кодирования.

- **Сэкономленные вызовы** — `Σ min(2, |C_t|)` по отказанным targets, доля от всех вызовов при K = 2.
- **Потерянная экономия** — `Σ (S − O)` по отказанным useful-delta targets, доля от `Σ (S − O)` по всем targets. Это верхняя граница потерь: selector мог и не найти лучшую базу.
- **FN** — доля useful-delta targets, получивших отказ.

Выбирается уровень с максимумом сэкономленных вызовов при **потерянной экономии ≤ 0.5 %** и **FN ≤ 1 %**. При равенстве берётся меньший уровень. Если подходит только `L = 0`, отказ не вводится. Правило и пороги заданы в коде (`S3_LEVELS`, `S3_LOST_MAX`, `S3_FN_MAX` в [simple_selector.py](../tools/simple_selector.py)) и после прогона не меняются.

Adversarial negatives — 8 случайных объектов по 64 KiB и 8 zlib-потоков реальных файлов pilot-v1 против баз файлового track без метаданных. Для них публикуется только сигнал (`best_shared`): oracle для них не считался, и в выбор уровня они не входят.

## 4. Запуск

`selector-s3.yml`: dispatch на `main`, admission, очередь `delsk-experimental`, 30 мин, artifact cap. Шаги:

1. Материализация pinned pilot-v1 store.
2. Пересборка X0 store. Queries `C_t` обязаны совпасть с retained run 37449333091.
3. `simple_selector.py features`, затем `simple_selector.py abstention`.

Natural bytes остаются в `RUNNER_TEMP`; в artifact идут только признаки (пары `shared/union`) и анализ. Анализ воспроизводится офлайн из retained `features.jsonl`.

## 5. Ограничения

Оценка in-sample, на тех же 18 families, что и selector. FN ≤ 1 % при ~100 useful targets — точечная оценка без узкого доверительного интервала (протокол §5). Для FN-гарантии 99 % нужен held-out с сотнями независимых useful targets.
